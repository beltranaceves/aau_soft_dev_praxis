# S02: Hyper-learning in Netcompany (Model Exam Paper)

## Source
Brandborg, A. (2017). Hyper-learning in Netcompany. Aalborg University.

## What This Is
A **student exam paper** — an example of how to apply the hyper-learning theory (Lyytinen et al., 2010) to analyze a real software development organization (Netcompany). This is the model for what you need to produce.

## Problem Statement
*How does an SDO hyper-learn, when its employee-base grows drastically?*

## Methodology
- **Single case study** — testing boundaries of well-formed theory
- **Case**: Netcompany (Danish SDO, back-end business solutions, grew from ~600 to ~1000 employees, 2015-2017)
- **Data**: Semi-structured interviews with 3 employees (consultant, senior consultant, specialist) on the same project (Solar — web-based storefront)
- **Analysis**: Coding statements into 4 learning routine categories

## Key Findings

### Distributed Gate Keeping
- Some evidence: employees become experts through project experience
- **But**: No explicit R&D role — expertise develops organically, not as explicit exploration
- Some R&D projects exist but only a few hours/week — slows parallel ambidexterity

### Brokering External Knowledge
- Netcompany limits scope by focusing only on back-end (frontend outsourced)
- **Heavy use of external courses** for foundational knowledge
- This shifts exploration to external vendors, slowing switching between exploration/exploitation

### Simple Design Rules & Artifacts
- Document templates are reused across projects
- Software components made generic and placed in a component catalogue
- **But**: These are built up and formalized over years — not the quick, informal rules described in theory

### Building Peer Networks
- Specialists jump between projects sharing expertise
- Informal peer help is the norm ("it's the person with knowledge who can help you")
- Company-wide forum with activity-based evaluation — functions as Q&A/FAQ
- **Most parallel ambidexterity here**: exploration through work tasks → sharing with peers → exploitation

## Discussion with Mintzberg's Organization Theory
- Netcompany shows signs of **formalization and standardization** as it grows
- This aligns with Mintzberg: as organizations grow, they formalize behavior
- In stable environments, organizations use standardization (skills, processes) rather than mutual adjustment
- But Netcompany still shows informal learning → environment is not totally stable
- **Conclusion**: A growing SDO may need to formalize even when there's a pull to hyper-learn, IF the environment is stable enough

## Key Takeaways for Your Own Analysis
1. Use **semi-structured interview data** and **code statements** against theoretical categories
2. Show where the case **fits** and **doesn't fit** the theory
3. **Discuss with another theory** (Brandborg uses Mintzberg; you can use any theory from the course)
4. A single case can test the boundaries of a theory
5. Be systematic: present each theoretical concept and the evidence for/against it
